MLEvolve

论文：MLEvolve: A Self-Evolving Framework for Automated Machine Learning Algorithm Discovery
arxiv：https://arxiv.org/abs/2606.06473

summary：又一篇自进化，旨在实现端到端的ml算法自动发现

针对自进化探索任务，目前的问题：

  1. information isolation：探索的不同路径之间不会通信。具体的逻辑是，探索算法时可能会有多个并行的worker，每个worker只会根据自己探索出的内容一点点精修，而无法感知其它worker的内容。（不过这里，所有节点都是从root节点开始的）
  2. 无法吸取教训
  3. 一次性重写，不会区分plan与coding（虽然无关，用codex的时候倒是体会到了这个问题）

解决方案：

  1. 渐进式蒙特卡洛算法，这个是主要的
  2. 记忆：领域知识库+全局记忆
    • 领域知识库：与任务类型相关的全局知识库，通过关键词匹配检索
    • 全局记忆：关键词匹配+faiss语义搜索，rrf（倒数排名融合）整合
  3. plan与code：除了解耦之外，coder有三种模式可选
    • base：从头开始
    • stepwise：按模块生成
    • diff：补丁

关键算法讲解：

  1. 首先整个流程被组织为一个图；可以认为每个点是一种ml算法。在每个分支上有一系列的算法（迭代得到的），这些分支之间还可能有连接。
  2. 边分为主边和参考边。主边为一个分支上的连续节点（保留顺序）；参考边表示某个节点整合了来自另一条链路中某个点的信息
  3. 奖励：每个算法的即时奖励可能为-1、1、2。没有跑通为-1，跑通为1，跑通且在当前链路sota为2
  4. 算出每个算法的即时奖励之后，会做反向传播（只在自己的链路里传播）
    • 所有访问次数加一
    • 所有得分增加对应奖励值
  5. 节点从root开始新增。每次新增有四种方案：
    • 从父节点单独扩展
    • 参考统一分支内最近的k个节点
    • 参考所有分支中表现最好的n个节点
    • 聚合不同分支，在root下新建一个分支
  6. 根据公式，选择从哪个节点继续
  7. 根据一系列规则决定如何修改
    • 单独扩展
    • 分支内进化：改分支连续t1次未提分
    • 跨分支进化：触发分支内进化条件，且已经用到预算的50%以上（时间/cost）
    • 聚合：整个系统连续t2次未提分
  8. 涉及挑选节点时，会根据倒数加权，为每个节点赋一个概率，分数越高选中概率越大，然后选出数个节点
  9. 将找出的节点打包给llm，生成下一个方案

上文的公式为

UCT(i)=Qi+c(t)ln(Nv+1)Ni+ϵUCT(i) = Q_i + c(t)\sqrt{\frac{ln(N_v + 1)}{N_i + \epsilon}}UCT(i)=Qi​+c(t)Ni​+ϵln(Nv​+1)​​

其中 QiQ_iQi​ 为节点i的平均奖励， NiN_iNi​ 为访问次数， NvN_vNv​ 为父节点访问次数。 c(t)c(t)c(t) 为探索常数，随时间逐渐减小。策略为选择UCT最大的节点。

这里引入了一些熵的思路。UCT后面的哪一项是探索项，优先选择“分支热门、节点冷门”的情况，旨在增加探索。探索常数会逐渐衰减，让系统逐渐从优先探索过渡到优先最好方案。
