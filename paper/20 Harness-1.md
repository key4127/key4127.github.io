# Harness-1

论文：Harness-1: Reinforcement Learning for Search Agents with State-Externalizing Harness    
arxiv：[https://arxiv.org/abs/2606.02373](https://arxiv.org/abs/2606.02373)

---

这篇文章是关于search agent的。

summary：将搜索结果提取出来，而不是只堆在对话记录里。这些信息由harness来维护。

具体来说harness通过query、精选集、证据图等信息生成一个状态，模型只会看到状态本身。状态由候选池、精选集、证据图、验证缓存（通过验证的文档优先级最高，不需要重复阅读）、文档评分

具体行为：
1. 搜索后：
    - 将每个文档通过bm25筛选出4个句子
    - 通过文档id和minhash-lsm（可以理解为相似度）对chunk去重
    - auto-seeding：第一次搜索的结果加入精选集，llm决定crud（*这个地方似乎和rl有关。在rl训练早期，模型似乎会搜索但不加入输出？*）
    - 渐进式降级
2. 关于精选集：
    - 每个文档有优先级排序
    - 文档达到容量上限（30）时，根据重要性排名驱逐
3. 渐进性降级
    - 打包system prompt、完整状态、最近对话、结果摘要，超标进入下一阶段
    - 保留搜索历史（assistant + user）和精选集，删除候选池内容
    - 将推理历史截断为100个字符，将状态限制在2000token
    - 从最旧轮次开始删除历史

想法：从workflow到react再到llm harness，我倾向于这是从框架主导到模型主导，又到框架和模型分庭抗礼。在这种情况下，出现了非常多相关的探索，探索各种能力究竟该由模型实现还是由框架实现。我个人认为目前的*观点*还是**将来**要由模型主导；但是在模型可以主导之前，框架应该承担多少工作？这篇文章就是把某些中间的任务分给了框架。
